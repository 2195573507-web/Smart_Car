# IMU 振动采集与自适应滤波清理设计

## 目标

删除仓库中 IMU 振动数据采集、振动特征分析、转速/PWM 自适应滤波及其跨端展示链路，将 IMU 启动流程收敛为静态标定后进入 READY，并保留 LSM303/BMI323 采样、数据锁、静态偏置/姿态 leveling 和标准数据融合。

## 不变边界

- 不修改 SCBP-V3 帧头、长度字段、CRC 或通用编码/解析行为。
- 不修改现有 `0x0202` IMU 标定状态和 `0x0208` 双 IMU 状态的负载长度、字段偏移或结构体布局。废弃的振动相关值固定为零，READY/FAILED 状态数值保持兼容。
- 保留 LSM303、BMI323 驱动、独立采样任务、数据锁、静态标定质量门限、leveling 和姿态输出。
- 不修改与 IMU 振动无关的雷达正常 PWM、音频、CSI 和服务器功能。

## 运行架构

STM32 `imu_boot_manager` 保留传感器 INIT/SELF_TEST，随后执行一个共享静态标定窗口。窗口闭合并且 LSM303 加速度、BMI323 加速度和陀螺仪均满足质量门限后，提交偏置与 leveling，发送兼容的静态状态/偏置通知并直接进入 READY；失败进入 FAILED。振动窗口、五档 PWM、VERIFY 和振动完成回调全部删除。

`imu_filter` 只保留固定 median 窗口和固定 `IMU_FILTER_ALPHA` IIR。`DualAHRS` 只保留固定 LPF、标准 Mahony/冗余姿态融合和现有时间戳降级策略；删除 notch、PWM 重力降权和任何 RMS/转速自适应选择。

ESPS3 的标定管理器只负责零 PWM 同步和静态标定完成确认，删除五档 PWM/振动事件推进。STM 服务不再把雷达状态送入 IMU 滤波。macOS 仅保留静态标定、双 IMU 状态和姿态/传感器遥测，删除 `0x24`/`0x26` 的振动模型、解析、存储和 UI。

## 协议处理

`0x0202` 仍为原 11 字节负载；静态标定期间报告原有阶段/样本计数，完成后报告 COMPLETE，PWM 和错误字段遵循原布局。`0x0208` 仍为原 16 字节负载；phase、进度、错误、时间戳字段保持原偏移，振动索引和 radar PWM 字段固定为零。振动结果消息 `0x0204`/`0x0206` 不再由任何端点生成、转发或解析。

## 风险与验证

主要风险是跨端状态值或负载偏移漂移，以及删除模块后残留符号。实现后执行：

1. 全仓搜索振动模块、状态、接口、消息 ID 和自适应滤波符号。
2. STM32 CM7 CMake/Ninja 构建并检查未定义符号、未使用包含和编译告警。
3. ESPS3 构建/静态检查，确认静态事件 ACK 链路仍可编译。
4. macOS SwiftPM 构建，确认静态标定和 `0x0202`/`0x0208` 解码仍通过。
5. 对 `0x0202`、`0x0208` 进行源码级长度/偏移断言；硬件传感器、UART、BLE 和雷达行为单独标记为未验证。
