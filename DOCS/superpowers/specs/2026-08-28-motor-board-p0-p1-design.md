# MotorBoard P0/P1 可靠性优化设计

## 1. 目标与范围

本次优化只覆盖 STM32H757 CM7 与四路电机驱动板之间的初始化、配置回读、
反馈有效性和故障停机。目标是在不改变既有运动学、轮子映射、编码器方向、
本地 PID 参数或 S3 控制协议的前提下：

- 初始化未完成或反馈未建立时，禁止非零 PWM 输出。
- 有效 `$MSPD` 反馈连续丢失 200 ms 时主动停机并重新初始化。
- 按实测 `$read_flash#` 文本逐字段验证板卡参数，避免每次上电盲写 Flash。
- 只接受与当前请求对应的配置响应；明确错误立即进入锁定故障。
- 为电池电压增加新鲜度判断，避免上报过期缓存。

本次明确不包含：

- P2 调度、临界区、CPU/栈、环形缓冲和任务轮询优化。
- M1-M4 映射、`ENCODER_DIR_SIGN`、转动方向和 PWM 符号规则。
- 切换到板端 `$spd`/`$MPID` 闭环。
- `$flash_reset#` 或其他会无条件重置板卡的命令。
- S3/App 协议字段和既有姿态安全门控重构。

## 3. 实测协议事实

用户提供的 `$read_flash#` 返回为纯文本行，顺序和字段如下：

```text
read_flash:OK!
Motor_Version:1.7.3
Motor_type:1
Dead_Zone:1600
Pulse_Line:11
Pulse_Phase:30
wheel_diameter:65.000
P:0.800    I:0.060    D:0.500
```

其中 `read_flash:OK!` 只表示回读响应开始，不能作为全部参数已验证的完成
标志。当前解析器的 `OK` 通用识别会在第一行提前结束 `s_read_flash_active`，
因此本次必须为回读建立独立的收集和完成判断。

## 4. 组件与修改位置

### 4.1 `motor_board_task.c`

负责 MotorBoard 生命周期状态、初始化序列、反馈 watchdog、目标准入和电池
时间戳。

拟修改内容：

1. 增加控制状态：`LOCKED`、`CONFIGURING`、`WAIT_FEEDBACK`、`READY`、`FAULT`。
2. 初始化任务从 `LOCKED` 开始；在 `$upload:0,1,1#` 后进入
   `WAIT_FEEDBACK`，至少收到两帧时间间隔在 2-100 ms 内的有效 `$MSPD` 才进入
   `READY`。
3. `motor_board_set_target_wheel_speeds()` 对非零目标检查 `READY`；在其他状态
   拒绝并保留停止状态，零目标继续调用现有 `motor_board_force_stop()`。
4. 记录最后有效 `$MSPD` 时间。运行状态超过 200 ms 未收到有效帧时，执行一次
   强制停止、清零目标、重置 PID/Ramp 和反馈计数，进入 `LOCKED`/初始化重试。
5. `$MSPD` 时间戳异常时继续使用现有的 PID 历史重置逻辑，但不把异常帧计入
   `READY` 的连续有效帧计数。
6. 保存最近电池帧的单调时间戳；超过电池新鲜度窗口后，
   `motor_board_get_battery_voltage()` 返回无效并记录 stale 状态。
7. 将初始化阶段和 watchdog 事件用有限频率日志记录，避免同一故障每个轮询周期
   重复打印。

### 4.2 `motor_board_protocol.c/.h`

负责把板卡文本解析成结构化的配置回读结果，并保持现有 `$...#`、CRLF/LF
兼容性。

拟修改内容：

1. 增加 `read_flash` 配置快照结构，至少包含 `Motor_type`、`Dead_Zone`、
   `Pulse_Line`、`Pulse_Phase`、`wheel_diameter` 的值和字段 bitmask。
2. `read_flash:OK!`、版本行和 `P/I/D` 行均作为回读行保存或解析；仅在五个必需
   字段全部出现且数值有限、范围有效时报告 `COMPLETE`。
3. 保留原始行日志，字段名匹配不区分大小写；数值解析拒绝截断、溢出、NaN、Inf
   和尾随非空字符。
4. 配置 ACK 解析改为提供原始响应、规范化命令名和明确成功/失败类别，由任务层
   绑定当前等待命令，不能由任意包含 `OK` 的文本推进其他步骤。
5. 不将板端 `P/I/D` 当作 STM32 本地 PID 的运行准入条件；该行只用于诊断。
6. 增加 `MB_Protocol_SendDeadzone(uint16_t)`，使任务层可以在回读明确不一致时
   发送 `$deadzone:1600#`；正常匹配时不发送。

### 4.3 `motor_board_task.h`

仅在任务层需要向其他模块暴露状态或新鲜度查询时增加最小只读接口；不修改
现有目标速度、强制停止和电池查询接口的语义。

## 5. 初始化与状态机

```text
LOCKED
  -> CONFIGURING: 任务启动，发送 $pwm:0,0,0,0# 和 $read_flash#
  -> CONFIGURING: 回读完整且参数匹配，跳过对应写命令
  -> CONFIGURING: 字段缺失/不一致，逐条写入不一致配置并等待对应 ACK
  -> CONFIGURING: 写入后再次 $read_flash#，五字段完整匹配
  -> WAIT_FEEDBACK: 发送 $read_vol#、$upload:0,1,1# 并等待反馈
  -> READY: 收到至少两帧连续、时间间隔正常的有效 `$MSPD`
  -> FAULT: 明确 NACK、配置回读格式错误或重复发送失败

READY
  -> LOCKED: 200 ms 无有效 `$MSPD`、响应超时触发链路重试、急停或上层安全门控
             撤销
```

进入 `LOCKED` 或 `FAULT` 的共同动作：

1. 清零目标速度。
2. 重置四路 PID 和 Ramp 当前目标。
3. 发送 `$pwm:0,0,0,0#`；发送失败必须记录错误。
4. 清除有效反馈计数和时间戳。
5. 不恢复旧的非零目标；只有重新完成初始化并进入 `READY` 后才接受新目标。

`MSPD` watchdog 和普通响应超时进入 `LOCKED`，按现有链路探测机制重试；每次重试
从零 PWM 和锁定状态开始，不能直接恢复到 `READY`。明确 NACK、回读格式错误或
重复发送失败进入 `FAULT`，保持零输出并降低日志频率，等待下一次系统复位或明确
的重新初始化入口。

## 6. 配置回读与按需写入

目标配置快照为：

```text
Motor_type=1
Dead_Zone=1600
Pulse_Line=11
Pulse_Phase=30
wheel_diameter=65.000
```

流程：

1. 先发送零 PWM，再请求 `$read_flash#`。
2. 收集直到必需字段齐全或响应超时；第一行 `read_flash:OK!` 不结束收集。
3. 五个字段都匹配时，跳过所有配置写入。
4. 仅对明确不匹配的字段发送对应设置命令，并逐条等待该命令的 ACK。
5. 写入完成后重新 `$read_flash#`，必须再次完整匹配；否则保持锁定/故障。
6. `$deadzone:1600#` 只在回读明确不是 1600 时发送，不因默认值或解析不确定而
   重复写入。

版本和板端 `P/I/D` 的处理：保存和记录原始值，允许版本或板端 PID 文本存在
   格式差异；它们不参与本项目本地速度闭环的放行判断。

## 7. 响应与错误处理

| 情况 | 处理 |
| --- | --- |
| 当前命令对应的成功 ACK | 推进当前状态机步骤 |
| 明确 `NACK/NOK/ERROR/FAIL` | 立即零 PWM，进入 `FAULT` |
| 其他命令的 ACK | 记录但不推进当前步骤 |
| `read_flash` 缺字段或数值非法 | 不写入、不放行，进入 `FAULT` |
| 配置响应超时 | 零 PWM，清理解析状态，重新链路探测 |
| `$read_vol#` 合法 `Battery:<finite>V` | 更新电压值和时间戳 |
| 电压查询超时或格式错误 | 保持轮速状态；电压标记无效/过期并记录 |
| `$MSPD` 帧字段非法 | 丢弃该帧，不刷新 watchdog |
| `$MSPD` 间隔超出 2-100 ms | 重置 PID 历史，不计入连续有效反馈 |

配置 ACK 必须带有当前等待命令的关联信息。若厂商只返回无法关联的通用
`OK!`，实现应保守地记录为未确认，不凭此推进需要逐命令确认的配置步骤。

## 8. 航向纠偏兼容性

本次不修改航向控制律。前进时航向纠偏仍通过左右轮速度差实现：

```text
right = v + w_corr * 193 / 2
left  = v - w_corr * 193 / 2
```

P0/P1 不对最终 PWM 取绝对值，也不额外乘方向符号。只有在 `READY` 且反馈有效
时，航向生成的四轮目标才会进入本地速度 PID。低速时某侧目标可能接近或跨过
零，是否强制“前进纠偏不反转”属于后续控制策略，不在本次 P0/P1 范围内。

### UART/台架验收

使用与本次代码匹配的镜像抓取 USART6：

1. 上电确认先发 `$pwm:0,0,0,0#` 和 `$read_flash#`。
2. 配置已经为 `1/1600/11/30/65` 时，确认不再重复发送对应写命令。
3. 改变一个参数后重新上电，确认只发送不一致字段并回读验证。
4. 确认 `$upload:0,1,1#` 后收到两帧正常 `$MSPD` 才允许目标进入 PID。
5. 运行中断开反馈，确认 200 ms 内发送零 PWM、清除目标并重新锁定。
6. 恢复串口后确认不会自动恢复旧目标，重新初始化后才可接受新目标。
7. 对 `$read_vol#` 做多次查询，确认电压时间戳和 stale 行为。

构建和主机测试只能证明源代码和解析逻辑；不能替代 USART6 电气、真实反馈
周期、编码器方向、无线链路或车辆安全验收。

## 10. 风险与回滚

| 风险 | 缓解措施 |
| --- | --- |
| 厂商固件字段大小写或顺序变化 | 字段名不区分大小写、允许乱序；缺字段时保持锁定，不盲写运行 |
| 板卡只返回通用 ACK | 不把无法关联的 ACK 当作逐命令确认；通过实际抓包补充映射 |
| 串口偶发丢帧触发停机 | 采用 200 ms watchdog，允许单帧丢失；记录反馈周期统计 |
| 失联后旧目标恢复造成突然运动 | 进入锁定时清零目标，READY 前拒绝非零目标 |
| 配置写入后板卡重启 | 本次不发送 `$MPID` 和 `$flash_reset#`；每一步都等待 ACK/回读 |

回滚只需恢复本次修改的 MotorBoard 源文件；不应回滚工作区中其他用户改动。
