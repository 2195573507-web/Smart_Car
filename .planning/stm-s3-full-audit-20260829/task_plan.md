# STM32H757 与 ESP32-S3 全量只读代码审计计划

> Historical snapshot. This audit predates the SRPv4 full switch; any SCBP
> names or paths below describe the audited baseline only and are deprecated.

## 目标

在不修改任何源代码、配置代码或生成代码的前提下，对当前工作树中的 STM32H757（CM7/CM4）与 ESP32-S3 实现完成可追溯的静态全量审计；经过至少 10 轮独立审计与文档修订，交付正式审计计划和总报告，并提出保留现有契约前提下的 STM32H757 双核最优任务分配方案。

## 当前阶段

阶段 5：静态验证与交付（已完成）

## 不可突破的边界

- 只读审计所有固件源代码；不得修改、格式化、生成或提交任何代码。
- 仅允许创建或修改本任务专用的 Markdown 规划、证据和报告文档。
- 不运行会重写生成物、缓存或固件产物的配置/构建命令。
- 当前源代码优先于历史文档；历史材料只作线索，所有结论回到当前文件和符号验证。
- 明确区分：确定事实、已有设计、推测原因、建议方案、未验证项。
- 源码静态证据不能替代烧录、UART/BLE 抓包、实时测量或整车验收。
- 保留 SRP/BLE ID、报文布局、UART/GPIO 所有权、轮序/几何、传感器标定和安全门控等既有契约；本任务不授权改变它们。

## 发现分级

| 等级 | 定义 |
|---|---|
| Critical | 可直接破坏安全控制、内存完整性或核心通信，且存在现实触发路径 |
| High | 可能导致失控、死锁、任务饿死、持续错误输出或关键恢复失败 |
| Medium | 明显降低可靠性、实时性、效率、可维护性或扩展安全性 |
| Low | 局部质量、可观测性、文档或一致性问题，短期运行影响有限 |
| Info | 已有设计、度量缺口或无需立即修改的改进机会 |

## 证据规则

每项发现必须尽量包含：`ID`、等级、置信度、分类、受影响核/模块、文件与符号、触发条件、机制、潜在影响、现有保护、建议、验证方法。缺少运行证据时明确标记为静态推断或待测量。

## 已做决策

| 决策 | 理由 |
|---|---|
| 使用独立 `.planning/stm-s3-full-audit-20260829/` | 根级规划文件属于旧任务，避免覆盖用户历史工作 |
| 正式交付放在现有 `DOCS/` | 遵循当前文档体系，不新建平行文档根 |
| 采用 12 轮而不是最低 10 轮 | 将底层、应用、跨芯片、效率、安全和双核设计分别复核 |
| 第三方/生成代码只审计集成与配置面 | 避免把供应商代码体量误称为项目自研代码审计 |
| 不执行构建 | 构建会更新产物或缓存，与“不要修改任何代码/只读审计”边界相比没有必要 |
